# 04 · 解锁尝试，以及一个决定性的单字节实验

## 结论先行

**这台机器的 Bootloader 无法解锁——不是技术不够，是 `splloader` 被 BootROM 整体校验。**

下面记录四次尝试，以及最后证明"此路不通"的那个实验。

---

## 背景：为什么改 SPL 是解锁的关键

Unisoc 的启动链：

```
BootROM(mask) → splloader → uboot → boot(kernel)
```

`gen_spl-unlock` 这类工具的套路是：**把 splloader 里的"校验函数调用"改成空操作**，让后续镜像跳过签名检查。

---

## 尝试一：看懂补丁在改什么

`gen_spl-unlock.exe` 会在当前工作目录生成 `spl-unlock.bin`。

对比原版，差异是 **64 个字节**：

```
偏移 0xA65C ~ 0xA7E3
原: 79 00 00 94  →  BL <某个函数>
新: 1F 20 03 D5  →  NOP ×4
```

反汇编（ARM64）：

```
0x0A640  mov  x0, #0x800
0x0A648  movk x0, #0x6500, lsl #16    → x0 = 0x65000800（本 SPL 的加载地址）
0x0A64C  movk x1, #0xb003, lsl #16    → x1 = 0xB003FE00
0x0A65C  bl   #0xa840                 ← 被 NOP 掉的调用
0x0A660  cbz  w0, #0xa66c             ← 返回 0 → 走成功分支
0x0A664  mov  w0, #5
0x0A668  bl   #0xa254                 ← 否则报错
```

继续跟进去，`0xA840` 是个跳转桩（`b 0xBAB4`），真正的函数做的是：

```
0xBAB4  ... 计算 0x65000800 处数据的哈希
0xBAFC  bl  #0xba08          与 0xB003FE00 处的值比对
0xBB00  cmp w0, wzr
0xBB04  cset w0, eq          返回比对结果
```

**所以这是一个镜像校验函数。** 原补丁把整个调用删掉，导致 `w0` 里是未定义的残留值，`cbz` 判断失败 → 走报错分支 → 设备卡死。

---

## 尝试二：在内存里执行补丁 SPL

把补丁 SPL 当 FDL1 载入 `0x65000800` 执行（不写 flash）。

**结果**：设备正常，可以开机，但 `miscdata[8192:8256]` 仍然是 64 个零 → **没解锁**。

整份 `miscdata` 只有 2 个字节变化（`0x2904`、`0x2905`，启动计数）。

---

## 尝试三：写进 flash

先验证写路径：

| 测试 | 结果 |
|---|---|
| 写 `misc`（1MB 全零） | 读回 `identical=True` |
| 写原版 `splloader`（66248 字节非零） | 读回 `identical=True`，**设备正常启动** |

确认可靠后，写入补丁版：

**结果：设备黑屏，长按电源无反应。**

通过 BROM 回写原版 → 恢复正常。

---

## 尝试四：自己做一个更精细的补丁

既然 NOP 掉调用会破坏控制流，那就**保留调用、强制返回成功**：

```
0xA660: cbz w0, #0xa66c  →  mov w0, #0     (52 80 00 00)
0xA664: mov w0, #5       →  b #0xa66c      (02 00 00 14)
```

反汇编验证无误。

**结果：仍然黑屏。**

---

## 决定性实验：改一个不涉及代码的字节

到这里有两种可能：

| 可能 | 含义 |
|---|---|
| A. 补丁逻辑不对 | 还有机会 |
| B. 镜像受保护 | 彻底没戏 |

**区分方法**：往**全零填充区**改 1 个字节。

- 填充区不含任何代码，理论上不可能影响启动
- 但如果镜像被整体哈希校验，改一个字节就会失败

### 操作

```
原版 splloader 中，偏移 0x0FC09 开始有 519 字节的全零区
在其中间 0x0FD0C 写入 0xAA
```

### 结果

**设备完全黑屏，长按电源无反应。** 写回原版 → 立刻恢复。

### 结论

**`splloader` 被 BootROM 整体校验。任何字节改动都会导致拒绝加载。**

```
改 SPL 内容 → 哈希不匹配 → BootROM 拒绝执行 → 设备黑屏
```

---

## 方法论：怎么判断一台 Unisoc 设备能不能解锁

```
1. 能进 BROM 吗？（VID_1782 PID_4D00）
   不能 → 结束
2. 能执行 CVE 吗？（读到 SPRD3 + FDL1 version）
   不能 → 结束（BROM 已修复）
3. 往 splloader 填充区改 1 字节，能启动吗？
   不能 → 镜像受签名保护，解锁无望 ← 本机属于这里
   能   → 可以继续尝试真正的补丁
```

**第 3 步花 3 分钟，能省掉几天白工。**

---

## 恢复流程（每次失败都用它）

BROM 在**芯片掩膜 ROM** 里，不依赖 flash 内容 —— 所以黑屏也能救：

```
1. 拔线
2. 按住音量减 + 电源
3. 插线，保持按住
4. 运行恢复脚本：把原版 splloader 写回去
5. 拔线，长按电源 10 秒，开机
```

本次实验共恢复 **3 次**，每次约 3 分钟，全部成功。

---

## 顺带排除的路线

| 路线 | 结果 |
|---|---|
| `misc` 写 `boot-fastboot` | uboot 忽略，正常开机 |
| 音量上 + 电源 | 只进 BROM，无 fastboot |
| 音量下 + 电源 | 同上 |
| USB 设备监听 10 分钟 | 从 BROM(4D00) 直接跳到系统(5D20)，**无 any fastboot 设备** |

**这台机器没有 fastboot 通道。**
